# PRD — SAR System Check Serial별 Worst 선정 도구 (HTML)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.15 (2026-11-20) — Normalize to 1 W 소수 둘째 자리 |
| 대상 산출물 | `sar_worst.html` (브라우저 단일 파일) |
| 동일 로직 보조 도구 | `sar_worst.py` (명령줄용, 결과 동일) |
| 상태 | 기능 구현 완료 · 테스트 파일 검증 완료 · **실제 시험 엑셀 검증 전** |

---

## 1. 배경과 문제

SAR 시험에서는 측정 전에 시스템 체크(System Check)를 하고, 그 결과를 엑셀로 남깁니다. 시험 보고서에는 **같은 Dipole(Serial 번호)로 측정한 시스템 체크 중 가장 나쁜(worst) 결과**를 골라 Plot 번호를 매겨야 합니다.

지금은 이 작업을 사람이 직접 합니다.

- 여러 날짜, 여러 파일에 흩어진 시스템 체크 데이터를 서로 비교해야 합니다.
- Serial마다 1g·10g Delta(%)를 비교해서 worst를 찾아야 합니다.
- 보고서 양식(그림 1)에 옮겨 적고 번호를 붙여야 합니다.

시간이 오래 걸리고, 동률 판단이나 옮겨 적기에서 실수가 생기기 쉽습니다.

## 2. 목표

1. 시스템 체크 엑셀을 **여러 개 한 번에** 넣으면(필요하면 **검토 기간**을 정해서), **모든 파일의 데이터 값을 비교해 Serial 번호별로 worst를 자동으로 골라** 번호를 붙입니다.
2. 엑셀은 **합치지 않고 파일별로 정리**해서, 결과를 **파일마다 시트 하나씩, 보고서 양식(그림 1)과 똑같은 엑셀**로 내려받을 수 있습니다.
3. 설치 없이 **HTML 파일을 더블클릭해서** 쓸 수 있고, 데이터는 **PC 밖으로 나가지 않습니다**.

### 목표가 아닌 것

- 시스템 체크 합격/불합격(±10 %) 판정
- 원본 엑셀 수정 (원본은 읽기만 함)
- `.xls`(옛 엑셀 형식) 지원

## 3. 사용자

| 사용자 | 하는 일 |
|---|---|
| SAR 시험 엔지니어 | 시스템 체크 엑셀을 넣고, worst 결과를 확인하고, 결과 엑셀을 보고서에 붙임 |
| 시험 보고서 검토자 | Worst Summary 시트에서 선정 근거와 원본 위치를 확인 |

## 4. 사용 흐름

1. `sar_worst.html`을 Chrome 또는 Edge로 엽니다.
2. 시스템 체크 엑셀을 화면에 끌어다 놓거나 클릭해서 고릅니다. 여러 번 나눠 넣어도 모두 비교 대상에 들어갑니다.
3. 필요하면 **기준 엑셀**(`systemcheckdate.xlsx`, test_date 도구 결과)도 같은 곳에 넣습니다. 자동으로 인식해 기준 엑셀과 날짜·대역(·SAR Lab)이 같은 측정 건만 정리합니다.
   필요하면 **검토 기간**(YYYY-MM-DD ~ YYYY-MM-DD)을 고릅니다. 비워 두면 전체 기간입니다.
4. 화면에서 요약, Serial별 Worst 표를 보고, 결과 미리보기에서 파일 탭을 눌러 파일별 시트를 확인합니다.
5. **결과 엑셀 다운로드**(위쪽 패널 또는 결과 화면의 요약 옆)를 눌러 `SystemCheck_Worst.xlsx`를 받습니다. 브라우저의 기본 다운로드 폴더에 저장됩니다.
6. 처음부터 다시 하려면 **초기화**를 누릅니다.

## 5. 기능 요구사항

### 5.1 입력

| ID | 요구사항 |
|---|---|
| IN-1 | `.xlsx`, `.xlsm` 파일을 여러 개 받는다. 끌어다 놓기와 파일 선택 둘 다 지원한다. |
| IN-2 | 파일을 여러 번 나눠 넣어도 이전 파일과 함께 비교한다. 같은 이름의 파일을 다시 넣으면 건너뛰고 경고를 띄운다. |
| IN-3 | `.xls`나 엑셀 임시 파일(`~$`로 시작)은 읽지 않고 경고를 띄운다. |
| IN-4 | 한 파일 안의 모든 시트를 읽는다. 시스템 체크 표가 없는 시트는 건너뛴다. |
| IN-5 | 날짜, Type, Serial, 측정값이 모두 같은 측정 건이 여러 파일에 있으면, **각 파일 시트에는 그대로 보여 주고 worst 비교에서는 한 번만 센다**. 경고로 알린다. |

### 5.2 원본 양식 인식

원본 양식은 두 가지가 확인됐고, 둘 다 자동으로 인식해야 합니다.

| 양식 | 한 측정 건의 행 | 특징 |
|---|---|---|
| A (2줄) | 1g, 10g | 그림 1과 같은 양식 |
| B (4줄) | 1g, 8g, 10g, APD(4cm^2) | 맨 앞에 측정자(test by) 열, Area Scan, Est./Zoom Ratio, SAR System, DAE & Probe 열이 더 있음 |

| ID | 요구사항 |
|---|---|
| PA-1 | **측정 건 구분**: `1g`가 적힌 행부터, 라벨(8g/10g/APD…)이 이어지는 행까지를 한 측정 건으로 본다. |
| PA-2 | **헤더 찾기**: 첫 측정 행 바로 위 최대 8줄을 헤더로 본다. 병합된 헤더는 병합 범위의 모든 열에 같은 제목이 있는 것으로 본다. |
| PA-3 | **열 찾기**: 헤더 글자로 열을 찾는다. 대소문자는 무시한다. |
| PA-4 | **Delta 열**: 헤더에 `delta`가 있는 열 가운데, 그 열의 값이 같은 행의 두 값 A, B로 `(A − B) / B × 100`이 되는 열을 고른다(허용 오차 ±0.015 + 0.2 %). 헤더 후보가 없으면 모든 열에서 같은 방식으로 찾는다. 빨간 글씨 열(Est./Zoom Ratio)처럼 다른 식으로 계산된 열은 고르지 않는다. |
| PA-5 | **보조 규칙**: Normalize 열이나 Target 열을 헤더로 못 찾으면 PA-4에서 찾은 A, B를 쓴다. 날짜 열은 모든 측정 건에서 날짜로 읽히는 열, Type 열은 `D숫자…` 형태인 열, Liquid 열은 라벨 열 바로 왼쪽의 글자 열을 쓴다. |
| PA-6 | **Delta가 비어 있을 때**: 수식만 있고 계산된 값이 없으면 `(Normalize − Target) / Target × 100`으로 계산한다. |
| PA-7 | **날짜 형식**: `M-D-YYYY`, `M/D/YYYY`, `M.D.YYYY`, `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYY.MM.DD`, 엑셀 날짜 값을 모두 읽는다. |

**헤더로 열을 찾는 규칙**

| 열 | 헤더에 들어 있는 글자 |
|---|---|
| 날짜 | `date` |
| Type | `type` (단어 단위) |
| Serial | `serial` |
| Zoom Scan | `zoom` (단, `ratio`나 `est.`가 함께 있으면 제외) |
| Normalize | `normaliz` |
| Target | `target` |
| Liquid | `liquid` 또는 `ELI` |
| Delta 후보 | `delta` |

### 5.3 검토 기간

| ID | 요구사항 |
|---|---|
| PD-0 | 검토 기간 영역은 **접기/펼치기**로 한다. 기본은 접혀 있고, 접혀 있어도 제목 옆에 현재 기간(`전체 기간` 또는 `시작일 ~ 종료일`, 비운 쪽은 `처음`/`끝`)을 보여 준다. 시작일이 종료일보다 늦으면 자동으로 펼친다. |
| PD-1 | 시작일 ~ 종료일을 달력 칸으로 고른다. 값은 `YYYY-MM-DD`이고 **두 날짜 모두 포함**한다. 한쪽만 골라도 된다(시작일만 → 그날 이후 전부, 종료일만 → 그날까지 전부). |
| PD-2 | 기간 밖의 측정 건은 **worst 비교와 파일별 시트 모두에서 뺀다**. |
| PD-3 | 기간을 정하면 날짜를 읽지 못한 측정 건도 뺀다. |
| PD-4 | 두 칸을 모두 비우면 전체 기간을 검토한다(기존 동작). **전체 기간** 버튼으로 두 칸을 한 번에 비운다. |
| PD-5 | 기간 안에 측정 건이 없는 파일은 **시트를 만들지 않고**, 요약 아래에 그 파일 이름을 알린다. 넘버링·시트 이름은 남은 파일만으로 정한다. |
| PD-6 | 시작일이 종료일보다 늦으면 오류 문구를 띄우고 아무것도 검토하지 않으며 다운로드 버튼을 끈다. 기간 안에 측정 건이 하나도 없을 때도 안내 문구를 띄우고 다운로드 버튼을 끈다. |
| PD-7 | 기간 칸 옆에 불러온 데이터의 처음~마지막 날짜를 보여 준다. |
| PD-8 | 기간을 바꾸면 화면이 바로 다시 그려진다. 파일을 더 넣어도 기간 설정은 유지된다. 페이지를 새로 고치면 지워진다. |
| PD-9 | 기간을 정하면 결과 파일 이름에 기간을 붙인다: `SystemCheck_Worst_시작일~종료일.xlsx`(비운 쪽은 `처음`/`끝`). |
| PD-10 | Python은 `--from YYYY-MM-DD`, `--to YYYY-MM-DD` 옵션으로 같은 기능을 제공한다. 잘못된 형식이나 시작일 > 종료일이면 멈추고 알린다. |

### 5.3a 기준 엑셀 (System Check Date)

input 폴더의 `systemcheckdate.xlsx`(test_date 도구 결과: `No. | System Check Date | 대역 (MHz) | SAR Lab.`)와 첨부한 시스템 체크 엑셀을 비교해, **같은 날짜·같은 시스템(대역)** 측정 건만 정리한다.

| ID | 요구사항 |
|---|---|
| RF-1 | **자동 인식**: 넣은 파일에서 시스템 체크 데이터('1g' 측정 건)를 못 찾았고, 헤더에 `System Check Date`와 대역 열(`MHz`/`대역`/`Band`/`Freq`)이 있는 표가 있으면 기준 엑셀로 쓴다. Lab 열(`Lab`)은 있으면 쓴다. 여러 개 넣으면 행을 합친다. |
| RF-2 | 기준 엑셀 행의 대역 칸은 숫자를 모두 읽고(`5750/5800` → 둘 다) 각각 가장 가까운 시스템 대역으로 바꾼다. Lab 칸은 `SAR 4`/`4` → 4. |
| RF-3 | **측정 건의 대역**: 헤더에 `freq`/`MHz`/`GHz`가 있는 열이 있으면 그 값의 가장 가까운 시스템 대역(정확히 중간이면 둘 다). 없으면 Type: `D숫자` → 그 숫자의 가장 가까운 대역(`D2450V2` → 2450), `D숫자GHz` → 그 GHz 안의 시스템 대역 전부(`D5GHzV2` → 5250/5600/5750/5800). 둘 다 없으면 대역 조건을 보지 않는다. |
| RF-4 | **측정 건의 SAR Lab**: 헤더에 `Lab` 또는 `SAR System`이 있는 열의 값(`SAR 4`/`4`) → 없거나 못 읽으면 측정 건의 행들(라벨·Type 열 제외)에서 `SAR 4`/`SAR4`/`SAR-4` 형태의 칸(원본 Plot 칸 등). 없으면 Lab 없음. |
| RF-5 | **매칭**: 기준 엑셀에 (날짜 같음) AND (대역이 하나라도 겹침) AND (측정 건에 Lab이 있으면 Lab 번호 같음) 인 행이 있어야 한다. 측정 건에 Lab이 없으면 날짜·대역만 본다. 날짜를 못 읽은 측정 건은 뺀다. |
| RF-6 | 맞지 않는 측정 건은 **worst 비교와 파일별 시트 모두에서 뺀다**(검토 기간과 같은 방식, 기간과 함께 적용). 맞는 측정 건이 없는 파일은 시트를 만들지 않는다. |
| RF-7 | 화면: `기준 엑셀` 줄에 파일 이름·건수·Lab 목록, **기준 해제** 버튼. 파일 목록에 `기준: 파일명 (N건)`. 요약에 `기준 엑셀과 안 맞아 빠진 측정 건` 수. |
| RF-9 | **시스템 체크 없음 오류(빨간색)**: 기준 엑셀에 날짜가 있는 행(기간 안) 중 날짜·대역·Lab이 맞는 시스템 체크 측정 건이 하나도 없는 행은 **오류**로, 위쪽 패널(경고 아래)에 빨간 테두리·빨간 글씨 상자로 `날짜 · 대역 MHz · SAR Lab — 시스템 체크 없음` 목록을 보여 준다. 시스템 체크 엑셀을 넣은 뒤에만 보이고, 결과가 0건이어도 보인다. 요약에 `시스템 체크 없음 (오류)` 건수. Python은 `[오류]` 줄로 출력(터미널이면 빨간색). 결과 엑셀에는 넣지 않는다. |
| RF-8 | Python은 입력(기본 `input/` 폴더)에 섞인 기준 엑셀을 같은 규칙으로 자동 인식해 같은 결과를 낸다. |

시스템 대역: 13.5, 750, 835, 1750, 1900, 2300, 2450, 2600, 3500, 5250, 5600, 5750, 5800, 6000, 8000 MHz (test_date 도구와 같음).

### 5.4 Worst 선정

| ID | 요구사항 |
|---|---|
| WS-1 | 엑셀 표는 합치지 않고, **모든 파일의 데이터 값을 비교 대상**으로 삼아 **Serial 번호가 같은 측정 건끼리** 묶는다. 다른 파일에 있는 같은 Serial도 한 묶음이다. |
| WS-2 | Serial은 대소문자와 공백을 무시하고 비교한다. 숫자로 저장된 `1205.0`은 `1205`로 본다. |
| WS-3 | Serial이 비어 있는 측정 건은 결과 표에는 넣지만 worst 판정에서 빼고 경고를 띄운다. |
| WS-4 | 묶음마다 worst를 하나 고른다. 기준은 아래 순서다. |
| WS-5 | 8g, APD 행은 판정에 쓰지 않는다. |
| WS-6 | **번호 없는 시트 보완**: Serial별 worst를 정한 뒤 worst 번호가 하나도 없는 파일(시트)이 있으면, **그 파일의 모든 측정 건(Serial 무관, Serial이 빈 측정 건 포함)** 중에서 같은 Worst 기준으로 하나를 골라 번호를 붙인다. 이 번호도 NO-2의 순서에 끼워 전체 번호를 다시 매긴다. |

**Worst 기준** (소수 둘째 자리로 반올림한 절댓값으로 비교, 부호 무시)

1. **|1g Delta|**가 가장 큰 측정 건
2. 1g가 같으면 **|10g Delta|**가 더 큰 측정 건
3. 둘 다 같으면 **먼저 측정한(날짜가 빠른) 측정 건**. 결과 엑셀의 번호 칸에 동률 메모를 단다.

**선정 근거 표기**: `측정 1회` / `1g 최대` / `1g 동률 → 10g 로 결정` / `1g·10g 완전 동률 → 먼저 측정된 데이터` / `번호 없는 파일 → 파일 전체 worst`(동률로 정해졌으면 괄호로 덧붙임)

### 5.5 번호 매기기

| ID | 요구사항 |
|---|---|
| NO-1 | worst로 뽑힌 측정 건의 **Plot No.** 칸에 1부터 번호를 붙인다. |
| NO-2 | **넘버링 순서는 하나로 고정한다**: 파일을 아래 '파일 순서' 규칙으로 정렬한 뒤, 첫 파일 시트부터 각 시트 안에서 위에서부터 번호를 붙인다. 화면에 순서를 고르는 칸은 두지 않는다. |
| NO-6 | **파일 순서**: 파일 이름(확장자 제외)에 번호가 있으면 **그 번호 순서대로** 정렬한다. 이름에서 처음 나오는 숫자로 비교하고, 같으면 이어지는 숫자, 그래도 같으면 이름으로 비교한다. 번호가 없는 파일은 번호 있는 파일들 뒤에 불러온 순서대로 둔다. |
| NO-7 | 파일 순서는 넘버링뿐 아니라 결과 엑셀의 시트 순서, 화면의 파일 목록(`1. 파일명`)과 탭 순서에도 똑같이 적용한다. |
| NO-5 | 번호는 측정 건에 붙는다. 같은 측정 건이 여러 파일 시트에 있으면 그 시트들에 같은 번호가 붙는다. |

**파일 순서 예시**

| 넣은 파일 | 정렬 결과 | 이유 |
|---|---|---|
| `3_A`, `1_B`, `2_C` | `1_B` → `2_C` → `3_A` | 앞쪽 번호 1, 2, 3 |
| `A_3`, `B_1`, `C_2` | `B_1` → `C_2` → `A_3` | 숫자가 뒤에 있어도 번호 순서 |
| `Check_10`, `Check_2` | `Check_2` → `Check_10` | 글자 순서가 아니라 숫자 크기로 비교 |
| `SC_2024-03-05`, `SC_2024-02-26` | `SC_2024-02-26` → `SC_2024-03-05` | 처음 숫자(2024)가 같아 다음 숫자까지 비교 |
| `NoNum`, `1_B` | `1_B` → `NoNum` | 번호 없는 파일은 뒤 |

시트 구성: **넣은 엑셀 파일마다 시트 하나**(불러온 순서) + 마지막에 **Worst Summary** 시트.

**다운로드**

| ID | 요구사항 |
|---|---|
| SH-1 | **파일 이름에 `SAR숫자`가 있으면 그 부분만 시트 이름으로 쓴다**(예: `Liquid and System Check Table SAR11.xlsx` → `SAR11`, `SAR 4 backup.xlsx` → `SAR 4`). 없으면 첨부한 엑셀 파일 이름과 같게 한다(확장자만 뺌, 예: `1_A_Feb.xlsx` → `1_A_Feb`). 대소문자·공백·기호는 원본 그대로 둔다. |

| SH-7 | Worst Summary 시트에서 Worst 표 아래 한 줄을 띄우고 I~L열에 **시트 이름 ↔ 원본 파일 이름 대응표**(시트 이름, 원본 파일 이름, 측정 건수, 비고)를 넣는다. 이름이 바뀐 시트는 비고에 이유를 적는다. |

| SH-4 | 시스템 체크 데이터가 없는 파일은 시트를 만들지 않고 경고를 띄운다. |

#### 파일 시트 — 그림 1과 같은 양식

```
| Date Tested | System Dipole    | T.S. Liquid | Measured Results          | Target       | Delta  | Plot No. |
|             | Type | Serial #  |             | Zoom Scan to | Normalize  | (Ref. Value) | ±10 %  |          |
|             |      |           |             | 100 mW       | to 1 W     |              |        |          |
```

| ID | 요구사항 |
|---|---|
| OUT-1 | 헤더는 2줄이고, System Dipole, T.S. Liquid, Measured Results 칸을 그림 1처럼 병합한다. |
| OUT-2 | 서식은 그림 1과 같게 한다. 베이지색 헤더(`#D8CFB0`), 검은 얇은 테두리, Arial 10, 가운데 정렬. |
| OUT-3 | **날짜는 `yyyy-mm-dd`로 쓴다**(예: `2-27-2024` → `2024-02-27`). |
| OUT-4 | 측정 건마다 1g, 10g 행을 넣는다. **원본에 8g나 APD 행이 있으면 그 행도 같은 양식으로, 원본 순서대로 넣는다.** |
| OUT-5 | 날짜, Type, Serial, Liquid, Plot No. 칸은 그 측정 건의 행 수만큼 세로로 병합한다(2줄 또는 4줄). |
| OUT-6 | 소수 자릿수: Zoom Scan `0.00`, **Normalize `0.00`**, Target `0.00`, Delta `0.00`. 화면 미리보기도 같다. |
| OUT-7 | 각 파일 시트 안에서 측정 건을 날짜순으로 정렬한다. 같은 날짜는 원본 순서를 따른다. |
| OUT-8 | worst 번호는 굵은 글씨로 쓰고 색은 칠하지 않는다. |
| OUT-9 | 헤더 2줄은 틀 고정한다. |

결과에 넣지 않는 원본 열: 측정자(test by), Area Scan, Est./Zoom Ratio, SAR System, DAE & Probe, 원본의 Plot 값(예: `SAR 4`).

#### 마지막 시트: Worst Summary

| Plot No. | Serial # | Type | Date Tested | 1g Delta (%) | 10g Delta (%) | 측정 횟수 | 비교 파일 수 | 선정 근거 | 원본 |
|---|---|---|---|---|---|---|---|---|---|

- **원본**: `파일명/시트명 (행 번호)` 형식이라, 검토자가 원본 위치를 바로 찾을 수 있다.
- **측정 횟수**: 그 Serial로 측정한 건수.
- **측정 횟수**는 파일 간 중복을 뺀 건수다. 파일 전체 worst(WS-6) 행은 그 파일의 측정 건수, 비교 파일 수는 1이다.
- **비교 파일 수**: 그 Serial의 측정 건이 들어 있는 파일 수.

## 7. 경고와 예외 처리

| 상황 | 처리 |
|---|---|
| `.xls` 또는 다른 형식 | 읽지 않고 경고 |
| 파일이 깨져서 열 수 없음 | 그 파일만 건너뛰고 경고 |
| 날짜, Type, Delta 열을 못 찾음 | 그 시트를 건너뛴다. 같은 파일의 다른 시트에서 데이터를 읽었으면(예: `Dipole` 시트) **경고하지 않고**, 파일 전체에서 데이터를 못 찾았을 때만 시트별로 경고 |
| 1g 아래에 10g 행이 없음 | 그 측정 건을 건너뛰고 경고 |
| Type이 비어 있음 | 그 측정 건을 건너뛰고 경고 |
| Delta를 구할 수 없음 (값이 빈 양식 줄) | 그 측정 건을 **경고 없이** 건너뜀 |
| Serial 열이 없거나 Serial이 비어 있음 | 표에는 넣고 판정에서 빼고 경고 |
| 여러 파일에 같은 측정 건 | 각 파일 시트에 표시, worst 비교는 한 번만, 경고 |
| 같은 이름의 파일을 다시 넣음 | 건너뛰고 경고 |
| 데이터가 없는 파일 | 시트를 만들지 않고 경고 |
| 기간 안에 측정 건이 없는 파일 | 시트를 만들지 않고 요약 아래에 안내 |
| 시작일이 종료일보다 늦음 | 오류 문구, 검토하지 않음, 다운로드 버튼 끔 |
| 선택한 기간에 측정 건이 없음 | 안내 문구, 다운로드 버튼 끔 |
| 1g·10g 모두 동률 | 먼저 측정한 건을 고르고 번호 칸에 메모 |
| 기준 엑셀에 날짜·대역이 있는 행이 없음 | 경고, 기준 없이 동작 |
| 기준 엑셀과 맞는 측정 건이 없음 | 안내 문구, 다운로드 버튼 끔 |
| 기준 엑셀에는 있지만 맞는 측정 건이 없음 | **오류**: 위쪽 패널에 빨간 상자로 날짜·대역·Lab 목록 (RF-9) |

## 9. 남은 과제와 위험

| 구분 | 내용 | 대응 |
|---|---|---|
| **위험** | 실제 시험 엑셀로 검증하지 않았다. 양식 B의 헤더 이름은 이미지를 보고 추측했다. | 실제 파일로 한 번 돌려보고, 헤더 글자가 다르면 5.2의 열 찾기 규칙을 고친다. |
| 위험 | 헤더 철자나 표기가 달라지면(예: `Serial No.` 대신 `S/N`) 열을 못 찾을 수 있다. | 경고 메시지로 드러나게 했다. 새 표기가 나오면 규칙에 추가한다. |
| 제약 | 인터넷이 없으면 ExcelJS를 불러오지 못한다. | 필요하면 ExcelJS를 HTML 옆에 내려받아 오프라인으로 쓰게 바꾼다. |
| 제약 | 결과 엑셀의 날짜는 글자로 저장돼서, 엑셀 날짜 필터나 날짜 계산에 바로 쓸 수 없다. | 필요하면 날짜 값 + `yyyy-mm-dd` 표시 형식으로 바꾼다. |
| 주의 | 파일 이름의 **처음 숫자**로 정렬하므로, 이름 앞에 날짜나 모델 번호가 붙어 있으면 의도와 다른 순서가 될 수 있다(예: `D835_3`은 835로 정렬). | 순서를 정하고 싶으면 파일 이름 맨 앞에 `1_`, `2_`처럼 번호를 붙인다. |
| 제약 | 달력 칸의 표시 모양은 브라우저 언어를 따른다(한국어 Chrome/Edge는 `연도-월-일`). 내부 값은 항상 `YYYY-MM-DD`라 판정에는 영향이 없다. 기간 설정은 페이지를 새로 고치면 지워진다. | 필요하면 브라우저에 기억하게 바꾼다. |
| **위험** | 기준 엑셀 비교는 합성 파일로만 검증했다. 실제 원본에서 대역(Frequency 열 유무)·`SAR 4` 표기 위치가 다를 수 있다. | 실제 파일로 돌려 보고 RF-3·RF-4 규칙을 고친다. |
| 주의 | `D5GHzV2`처럼 여러 대역을 쓰는 Dipole은 Frequency 열이 없으면 그날 그 Lab의 5 GHz 대역 중 하나만 있어도 맞는 것으로 본다. | 원본에 주파수 열이 있으면 정확히 맞춘다. |
| 결정 필요 | 결과 엑셀에서 worst 행이나 번호 칸에 색을 칠할지 | 지금은 그림 1에 맞춰 굵은 글씨만 쓴다. |
