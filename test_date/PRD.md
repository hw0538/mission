# PRD — Test Date 도구 (HTML)

| 항목 | 내용 |
|---|---|
| 대상 산출물 | `test_date.html` (브라우저 단일 파일) |
| 상태 | v1 구현 완료, 샘플 2개로 검증 |

## 1. 배경과 문제

SAR 시험 데이터 엑셀은 대역별로 파일이 나뉘어 있고(예: `SAR test data_2.4GHz.xlsm`, `SAR test data_5GHz.xlsm`), 파일마다 시트가 10개 넘게 있습니다. 시트마다 "System Check Date" 표가 여러 개 있습니다. 그래서 **언제 어느 대역 시스템 체크를 했는지** 한눈에 확인하기 어렵습니다.

## 2. 목표

- 여러 엑셀의 모든 시트에서 System Check Date를 모아 **날짜 · 시스템 대역 · SAR Lab.** 요약 표 하나로 보여준다.
- 결과를 엑셀(`systemcheckdate.xlsx`)로 저장한다.

### 목표가 아닌 것

- 출처(파일/시트/행) 표시. 요약 표만 제공한다.
- Test Date, Tested By, Sample no. 등 다른 열 정리
- 시스템 체크 유효기간 판정

## 3. 사용자

SAR 시험 담당자. 결과 표를 보고 시스템 체크 날짜와 대역을 확인한다.

## 4. 사용 흐름

1. `test_date.html`을 Chrome 또는 Edge로 엽니다.
2. SAR 시험 데이터 엑셀 여러 개를 끌어다 놓습니다.
3. **실행** → 화면에 요약 표가 나옵니다.
4. **엑셀로 저장** → `systemcheckdate.xlsx`가 다운로드됩니다.

## 5. 기능 요구사항

### 5.1 입력

| ID | 요구사항 |
|---|---|
| IN-1 | `.xlsx`, `.xlsm` 파일을 여러 개 받는다. 끌어다 놓기와 파일 선택 둘 다 지원한다. |
| IN-2 | 각 파일의 **모든 시트**를 검사한다. |

### 5.2 처리

| ID | 요구사항 |
|---|---|
| PR-1 | 셀 텍스트가 `System Check Date`인 행을 표 헤더로 본다(대소문자·공백 무시). 같은 행에서 `Frequency (MHz)`, `SAR Lab.`, `Dipole`(헤더에 dipole이 들어간 열, 있을 때만) 열을 찾는다. 열 위치는 하드코딩하지 않는다(샘플 기준 A / O / E열). |
| PR-2 | 헤더 아래 행부터 다음 헤더 전까지를 한 표로 본다. System Check Date 칸에 날짜가 있는 행만 쓴다. |
| PR-3 | 시스템 대역: 13.5, 750, 835, 1750, 1900, 2300, 2450, 2600, 3500, 3700, 3900, 5250, 5600, 5750, 5800, 6000, 8000 (MHz) |
| PR-4 | 같은 행의 측정 주파수와 **가장 가까운** 시스템 대역을 고른다. |
| PR-4a | **13.5 대역은 다이폴 이름 `CLA-13`으로 판정한다.** 같은 헤더 행에 `Dipole`이 들어간 열이 있고 그 값이 `CLA-13`이면(`CLA13`, `cla-13` 포함, `CLA-130`은 제외), 또는 주파수 칸에 `CLA-13`이 적혀 있으면, 주파수 숫자와 상관없이 13.5 대역으로 본다. 다른 대역은 주파수 숫자로 판정한다(PR-4). |
| PR-5 | 측정 주파수가 두 대역의 **정확히 가운데**(예: 5775 MHz)이면 **두 시스템이 모두 필요하다**고 보고 두 대역 줄을 모두 만든다(5775 → 5750 줄 + 5800 줄). |
| PR-5b | PR-5의 두 대역 중 하나라도 **3000대역 시스템(3500/3700/3900)**이면 결과에 **확인 필요**로 표시한다. 3000대역에서 정확히 가운데인 주파수는 실제로 쓰지 않으므로, 나오면 원본 입력 오류일 가능성이 높다. 해당 주파수는 3050(2600+3500), 3600(3500+3700), 3800(3700+3900), 4575(3900+5250)이다. 두 줄은 그대로 만들고, 같은 키의 일반 행과 합쳐져도 표시는 유지한다. |
| PR-6 | (날짜, 대역, SAR Lab.)이 모두 같으면 한 줄로 합친다. |
| PR-7 | 정렬: **SAR Lab. 번호 오름차순**(SAR 2 < SAR 4 < SAR 10) → 날짜 오름차순 → 대역 오름차순. 번호가 없는 Lab 이름은 번호 있는 것 뒤에 글자순으로, 빈 Lab은 맨 뒤에 둔다. |

### 5.3 결과

| ID | 요구사항 |
|---|---|
| OUT-1 | 엑셀 파일명은 `systemcheckdate.xlsx`이다. **SAR Lab.별로 시트를 나누고**, 시트 이름은 첨부 엑셀의 SAR Lab. 값에서 `SAR 숫자` 부분만 쓴다(예: `SAR 10 (2F)` → `SAR 10`). `SAR 숫자`가 없으면 Lab 값 그대로, 빈 Lab은 `기타` 시트에 넣는다. 시트 순서는 Lab 번호순이고, No.는 시트마다 1부터 매긴다. |
| OUT-2 | 열: **No. \| System Check Date (YYYY-MM-DD) \| 대역 (MHz) \| SAR Lab. \| 비고** |
| OUT-3 | PR-5b 행은 행 전체를 노란색으로 칠하고, 비고에 `확인 필요: 3600.00 MHz는 두 시스템의 정확히 가운데`처럼 원래 주파수를 적는다. |
| OUT-4 | 숫자는 모두 **소수점 둘째 자리까지** 표시한다(예: 13.50, 2450.00, 비고의 3600.00 MHz). 엑셀의 대역 칸은 숫자 값으로 두고 표시 형식만 `0.00`으로 한다. |

### 5.4 화면

- 결과 표를 화면에 미리 보여준다. PR-5b 행은 노란색, 대역 옆에 ⚠, 비고 문구를 붙인다.
- 상태 줄에 "N개 파일에서 M건"을 표시하고, PR-5b 행이 있으면 "· 확인 필요 K건"을 덧붙인다.

## 6. 비기능 요구사항

- 브라우저 안에서만 처리한다(파일을 외부로 보내지 않음). ExcelJS 4.4.0은 CDN에서 불러온다.
- 1MB 안팎의 `.xlsm` 2개를 수 초 안에 처리한다.

## 7. 경고와 예외 처리

| 상황 | 동작 |
|---|---|
| `.xls` 등 다른 형식 | ".xlsx/.xlsm 파일만 읽을 수 있어요" 표시, 해당 파일 제외 |
| 날짜는 있는데 주파수가 비었거나 0 | 결과에서 **제외**. 단, Dipole이 `CLA-13`이면 13.5 대역으로 포함(PR-4a) |
| 날짜 서식이 걸린 0(1899-12-30으로 읽힘) | 날짜가 아닌 것으로 보고 제외 |
| 섹션 제목 행(예: "Product Specific 10-g 0 mm") | 날짜가 아니므로 무시 |
| 헤더가 없는 시트(예: `Project`) | 무시 |
| 파일을 열 수 없음 | 상태 줄에 파일명과 오류 표시, 나머지 파일은 계속 처리 |
| 결과 0건 | "System Check Date가 적힌 행을 찾지 못했어요" 표시 |

## 8. 검증 결과

**1차 (샘플 엑셀):** 2026-11-20, `input/`의 샘플 2개(`SAR test data_2.4GHz.xlsm`, `SAR test data_5GHz.xlsm`)를 headless Chrome에서 실제 HTML로 처리했습니다.

- 결과 16건, 동점 2건(5775 MHz). openpyxl로 따로 계산한 값과 일치했습니다. 당시에는 동점을 `5750/5800` 한 줄로 표시했는데, 지금은 PR-5에 따라 두 줄로 나뉩니다. 이 샘플에서는 그날 5750과 5800 줄이 이미 있어서 합치면 15건이 됩니다.
- 주파수 빈 행 1건(`WiFi2.4G_1 M1 R` 178행, 2026-11-04) 제외. 같은 날짜의 2450 결과는 다른 시트에도 있어서 정보 손실은 없습니다.
- PR-7 정렬은 샘플이 모두 SAR 4라서 가짜 데이터로 확인했습니다. 입력이 SAR 10, SAR 4, 빈칸, SAR 2, Lab A일 때 결과 순서는 SAR 2 → SAR 4(날짜순) → SAR 10 → Lab A → 빈칸입니다.
- 저장된 `systemcheckdate.xlsx`를 openpyxl로 다시 열어 헤더와 17행(헤더 포함)을 확인했습니다.

**2차 (PR-5 변경 후, 테스트용 엑셀):** 샘플 파일이 `input/`에서 빠져 있어서, 같은 구조(A열 날짜, E열 SAR Lab., O열 주파수, 헤더 2개, `Project` 시트)로 테스트 파일을 만들어 확인했습니다.

- 5775(SAR 4, 같은 날 5690 → 5750 있음) → 5750, 5800 두 줄. 5750 줄은 중복으로 합쳐집니다.
- 5775(SAR 10, 단독) → 5750, 5800 두 줄
- 날짜 없는 행, 주파수 없는 행, 섹션 제목 행, `Project` 시트는 모두 제외됐습니다.
- 결과 6건이고, 정렬은 SAR 2 → SAR 4 → SAR 10 순서입니다. 엑셀 6행에 노란 칸은 0개입니다.

주파수 → 대역 매핑 예: 2402/2412/2437/2440/2462/2480 → 2450, 5290 → 5250, 5530/5610 → 5600, 5690 → 5750, 5775 → 5750 + 5800(두 줄), 5855 → 5800.

**3차 (PR-5b, 테스트용 엑셀):** 3600, 3800, 4575, 3050이 각각 두 줄로 나오고, 두 줄 모두 노란색과 비고가 붙었습니다(10건). 5775와 3650은 표시되지 않았습니다. 같은 날 3450(→ 3500)과 3600이 있을 때 합쳐진 3500 줄에도 표시가 남았습니다. 엑셀에서도 비고 열과 노란 행을 확인했습니다.

**4차 (OUT-4):** 화면 대역 칸이 3500.00, 13.50처럼 나오고, 비고는 3600.00 MHz로 나왔습니다. 엑셀 C열은 값 3500에 표시 형식 `0.00`입니다.

**5차 (OUT-1 시트 분리):** 테스트용 엑셀(SAR 2, SAR 4, `SAR 10 (2F)`, 빈 Lab)로 확인했습니다. 시트는 `SAR 2`, `SAR 4`, `SAR 10`, `기타` 순서로 만들어졌고, No.는 시트마다 1부터 매겨졌습니다. 노란 행, 비고, `0.00` 표시 형식도 시트마다 유지됐습니다.

**6차 (PR-4a CLA-13):** 테스트용 엑셀로 확인했습니다. Dipole `CLA-13` + 주파수 13.56, Dipole `cla13` + 주파수 빈칸, 주파수 칸에 `CLA-13`인 경우 모두 13.50으로 나왔습니다. Dipole `D2450V2` + 2440은 2450.00으로 나왔습니다. Dipole `CLA-130` + 주파수 빈칸은 제외됐습니다.

## 9. 남은 과제와 위험

- 정확히 가운데인 주파수는 모두 두 시스템으로 처리합니다. 5775 외의 다른 경계값도 같은 규칙을 따릅니다(예: 2375 → 2300 + 2450). 5775 말고는 실제로 의도한 동작인지 아직 확인하지 않았습니다.
- 주파수가 빈 행은 조용히 제외합니다. 그 행이 그날의 유일한 기록이면 시스템 체크 기록이 누락될 수 있습니다.
- 5690 MHz처럼 대역 경계 근처의 주파수는 "가장 가까운 대역" 규칙을 따릅니다(5690 → 5750).
- 사용자가 보여준 시스템 체크 기록 표(다이폴 D6.5GHzV2 / D2450V2 / CLA-13 등)에는 `System Check Date` 헤더가 없어서 이 도구가 읽지 않습니다. PR-4a는 SAR 시험 데이터 표에 Dipole 열이 있거나 주파수 칸에 CLA-13이 적힌 경우에만 동작합니다. 실제 13.5 MHz 시험 데이터로는 아직 확인하지 못했습니다.
- 이 기록 표에 6.5 GHz 다이폴(D6.5GHzV2)이 보이지만, 시스템 대역 목록에는 6500이 없습니다(6000, 8000만 있음).
- 헤더 텍스트(`System Check Date`, `Frequency (MHz)`, `SAR Lab.`)가 바뀌면 표를 찾지 못합니다.
